## Background

### The TDD Cycle

| Step | You do | Rule |
|------|--------|------|
| 🔴 **Red** | Write **one** small test for behavior that doesn't exist yet. Run it. Watch it **fail**. | If it passes, the test isn't testing anything new. |
| 🟢 **Green** | Write the **minimum** code to make that test pass. | Faking it (e.g., `return 0`) is allowed. The next test will force real logic. |
| 🔵 **Refactor** | Clean up code and tests. Run the tests again. | Never change behavior during refactor. Tests must stay green. |

### Why It Matters in Agile and DevOps

- Tests **are** the spec: each one is an acceptance criterion turned into code.
- You get a regression suite for free, ready to run in CI on every commit (Lab 3.3).
- Small steps mean you're never more than a few minutes from working code.
- Code written to be testable tends to be simpler and less coupled.

### The Spec (from US3 PO Notes)

`calculate_discount(subtotal, code, today)` returns the discount **in cents** for a subtotal **in cents**.

| Code | Type | Value | Expires |
|------|------|-------|---------|
| `SAVE15` | percent | 15% | 2030-12-31 |
| `FIVEOFF` | fixed | $5.00 (500¢) | 2030-12-31 |
| `SUMMER20` | percent | 20% | 2025-08-31 |

- No code (empty or missing) → no discount
- Percent discounts round to the nearest cent; half a cent rounds **up**
- Codes ignore case and surrounding spaces
- Unknown code → error "That code isn't valid."
- A code is valid **through** its expiry date; the day after → error "This code has expired."
- The discount never exceeds the subtotal

> "One code per order" is a cart rule, not part of this function. Good unit tests stay focused on one unit.

### Cycle 1 – No code, no discount

🔴 Create the test file and write the first test.

```python

from discount import calculate_discount

TODAY = date(2026, 1, 15)


def test_no_code_gives_no_discount():
```

**JavaScript** – `discount.test.js`

```javascript

const TODAY = '2026-01-15';

test('no code gives no discount', () => {
  expect(calculateDiscount(7998, '', TODAY)).toBe(0);
});
```

Run the tests (`python -m pytest -v` or `npm test`). They **fail**: the module doesn't exist. That's a real red: the test describes something that isn't built yet.

🟢 Create `discount.py` / `discount.js` with the **least** code that passes:

```python
def calculate_discount(subtotal, code, today=None):
    return 0
```

```javascript
function calculateDiscount(subtotal, code, today) {
  return 0;
}
module.exports = { calculateDiscount };
```

Run again. Green. Yes, `return 0` is a fake. The next test will force real logic.

### Cycle 2 – Percent code

🔴 Add a test for `SAVE15`: 15% of $79.98 is $12.00.

```python
def test_tc_3_1_percent_code_takes_percentage_off():
    assert calculate_discount(7998, "SAVE15", TODAY) == 1200
```

```javascript
test('TC-3.1 percent code takes percentage off', () => {
  expect(calculateDiscount(7998, 'SAVE15', TODAY)).toBe(1200);
});
```

Run it. Red: the function still returns 0.

🟢 Make it pass with the simplest change you can think of. For example: if the code is `SAVE15`, return `round(subtotal * 0.15)` (Python) or `Math.round(subtotal * 0.15)` (JavaScript). Run again; **both** tests should be green.

### Cycle 3 – Triangulate the rounding

One passing example can hide a bug. **Triangulate**: add a second example that checks the same rule from a different angle. 15% of $29.90 is 448.5¢, which should round **up** to 449¢.

```python
def test_tc_3_1_percent_code_rounds_half_cent_up():
    assert calculate_discount(2990, "SAVE15", TODAY) == 449
```

```javascript
test('TC-3.1 percent code rounds half cent up', () => {
  expect(calculateDiscount(2990, 'SAVE15', TODAY)).toBe(449);
});
```

- **Python track:** this goes **red**. Python's `round()` uses "banker's rounding" (half to even), so 448.5 becomes 448. Fix it with whole-number math in cents: `(subtotal * 15 + 50) // 100`.
- **JavaScript track:** this probably passes already. That's fine: the test now **protects** the rounding rule if someone changes the code later. Switch to whole-number math anyway (`Math.floor((subtotal * 15 + 50) / 100)`) so both tracks avoid floating-point surprises with money.

🔵 **Refactor checkpoint:** is there duplication or a magic number (`15`) you'd like to name? Clean it up, rerun, stay green.

## Part 2: Your Cycles (25 min)

Now drive the rest of the spec yourself. For **each** row: write **one** test, run it red, write the minimum code to go green, then refactor. Commit to the cycle. No writing code before its test.

| Cycle | Test name (Python / JS) | Example | Expected |
|-------|-------------------------|---------|----------|
| 4 | `test_tc_3_1_fixed_code_takes_amount_off` / `TC-3.1 fixed code takes amount off` | 7998, `FIVEOFF` | 500 |
| 5 | `test_tc_3_2_code_ignores_case_and_spaces` / `TC-3.2 ... ignores case and spaces` | 7998 with `save15`, `Save15`, `" SAVE15 "` | 1200 each |
| 6 | `test_tc_3_3_unknown_code_is_rejected` / `TC-3.3 unknown code is rejected` | 7998, `BOGUS` | Error "That code isn't valid." |
| 7 | `test_tc_3_3_code_is_valid_on_its_expiry_date` + `..._rejected_after_its_expiry_date` | 1000, `SUMMER20` on 2025-08-31, then 2025-09-01 | 200, then error "This code has expired." |
| 8 | `test_tc_3_5_discount_never_exceeds_subtotal` / `TC-3.5 ...` | `FIVEOFF` with subtotals 300, 500, 501 | 300, 500, 500 |

Tips:
- **Cycle 4** is a good moment to refactor the `if` statements into a **table of codes** (a dictionary/object) like the one in the spec.
- **Cycle 5 and 8:** use a parameterized test so one test covers many values:
  - Python: `@pytest.mark.parametrize("code", ["save15", "Save15", " SAVE15 "])`
  - JavaScript: `test.each(['save15', 'Save15', ' SAVE15 '])('TC-3.2 code "%s" ...', code => { ... })`
- **Cycle 6:** create custom error types (`InvalidCodeError`, `ExpiredCodeError`). Check them with `pytest.raises(..., match="...")` or `expect(() => ...).toThrow(...)`.
- **Cycle 7:** this is why `today` is a parameter. A test that depends on the real clock passes today and fails later. **Control time in your tests.** In JavaScript, pass `today` as a `'YYYY-MM-DD'` string; ISO date strings compare correctly with `>`.

## Part 3: Review (10 min)

1. Run the full suite with verbose output. Every test name should read like a line of the spec.
2. **Mutation check:** temporarily break the code in each of these ways, one at a time, and run the tests. Did a test go red every time?
   - Change `>` to `>=` in the expiry check
   - Remove the `min(...)` cap on the subtotal
   - Remove `.upper()` / `.toUpperCase()`
3. Undo each change. Back to green.
4. Compare your code with a neighbor's. Different code, same tests passing: is either one wrong?

If a mutation **didn't** turn a test red, you've found a gap. Add the missing test.

## Key Takeaways

- **Red → Green → Refactor**, in small steps. Always watch the test fail first.
- Write the **minimum** code to pass; let the next test force the real logic.
- **Triangulate** with more than one example, especially around rounding and boundaries.
- Control anything non-deterministic, like the clock, so tests give the same result every run.
- The finished tests are a fast, readable **regression suite** and a living spec.

### Python – `discount.py`

```python
from datetime import date

CODES = {
    "SAVE15": {"type": "percent", "value": 15, "expires": date(2030, 12, 31)},
    "FIVEOFF": {"type": "fixed", "value": 500, "expires": date(2030, 12, 31)},
    "SUMMER20": {"type": "percent", "value": 20, "expires": date(2025, 8, 31)},
}


class InvalidCodeError(ValueError):
    pass


class ExpiredCodeError(ValueError):
    pass


def calculate_discount(subtotal, code, today=None):
    """Return the discount in cents for a subtotal in cents."""
    if not code or not code.strip():
        return 0

    discount = CODES.get(code.strip().upper())
    if discount is None:
        raise InvalidCodeError("That code isn't valid.")

    today = today or date.today()
    if today > discount["expires"]:
        raise ExpiredCodeError("This code has expired.")

    if discount["type"] == "percent":
        amount = (subtotal * discount["value"] + 50) // 100
    else:
        amount = discount["value"]
    return min(amount, subtotal)
```

### Python – `test_discount.py` (Cycles 4–8)

```python
from discount import ExpiredCodeError, InvalidCodeError, calculate_discount

def test_tc_3_1_fixed_code_takes_amount_off():
    assert calculate_discount(7998, "FIVEOFF", TODAY) == 500

@pytest.mark.parametrize("code", ["save15", "Save15", " SAVE15 "])
def test_tc_3_2_code_ignores_case_and_spaces(code):
    assert calculate_discount(7998, code, TODAY) == 1200

def test_tc_3_3_unknown_code_is_rejected():
    with pytest.raises(InvalidCodeError, match="That code isn't valid."):
        calculate_discount(7998, "BOGUS", TODAY)

def test_tc_3_3_code_is_valid_on_its_expiry_date():
    assert calculate_discount(1000, "SUMMER20", date(2025, 8, 31)) == 200

def test_tc_3_3_code_is_rejected_after_its_expiry_date():
    with pytest.raises(ExpiredCodeError, match="This code has expired."):
        calculate_discount(1000, "SUMMER20", date(2025, 9, 1))

@pytest.mark.parametrize("subtotal, expected", [(300, 300), (500, 500), (501, 500)])
def test_tc_3_5_discount_never_exceeds_subtotal(subtotal, expected):
    assert calculate_discount(subtotal, "FIVEOFF", TODAY) == expected
```

### JavaScript – `discount.js`

```javascript
const CODES = {
  SAVE15: { type: 'percent', value: 15, expires: '2030-12-31' },
  FIVEOFF: { type: 'fixed', value: 500, expires: '2030-12-31' },
  SUMMER20: { type: 'percent', value: 20, expires: '2025-08-31' }
};

class InvalidCodeError extends Error {}
class ExpiredCodeError extends Error {}

// Returns the discount in cents for a subtotal in cents.
// `today` is an ISO date string (YYYY-MM-DD).
function calculateDiscount(subtotal, code, today = new Date().toISOString().slice(0, 10)) {
  if (!code || !code.trim()) return 0;

  const discount = CODES[code.trim().toUpperCase()];
  if (!discount) throw new InvalidCodeError("That code isn't valid.");

  if (today > discount.expires) throw new ExpiredCodeError('This code has expired.');

  const amount = discount.type === 'percent'
    ? Math.floor((subtotal * discount.value + 50) / 100)
    : discount.value;
  return Math.min(amount, subtotal);
}

module.exports = { calculateDiscount, InvalidCodeError, ExpiredCodeError };
```

### JavaScript – `discount.test.js` (Cycles 4–8)

```javascript
const { calculateDiscount, InvalidCodeError, ExpiredCodeError } = require('./discount');

test('TC-3.1 fixed code takes amount off', () => {
  expect(calculateDiscount(7998, 'FIVEOFF', TODAY)).toBe(500);
});

test.each(['save15', 'Save15', ' SAVE15 '])('TC-3.2 code "%s" ignores case and spaces', code => {
  expect(calculateDiscount(7998, code, TODAY)).toBe(1200);
});

test('TC-3.3 unknown code is rejected', () => {
  expect(() => calculateDiscount(7998, 'BOGUS', TODAY)).toThrow(InvalidCodeError);
  expect(() => calculateDiscount(7998, 'BOGUS', TODAY)).toThrow("That code isn't valid.");
});

test('TC-3.3 code is valid on its expiry date', () => {
  expect(calculateDiscount(1000, 'SUMMER20', '2025-08-31')).toBe(200);
});

test('TC-3.3 code is rejected after its expiry date', () => {
  expect(() => calculateDiscount(1000, 'SUMMER20', '2025-09-01')).toThrow(ExpiredCodeError);
});

test.each([[300, 300], [500, 500], [501, 500]])('TC-3.5 subtotal %i gives discount %i', (subtotal, expected) => {
  expect(calculateDiscount(subtotal, 'FIVEOFF', TODAY)).toBe(expected);
});
```
